# The Open3D environment.
#
# Open3D is not installed in the main environment at all: version 0.19 ships precompiled
# PyTorch ops, and `open3d.ml.torch` raises unless the installed torch is 2.2.*:
#
#     open3d/ml/torch/__init__.py
#     raise Exception('Version mismatch: Open3D needs PyTorch version 2.2.*, ...')
#
# The main environment has moved well past that: SAM 3 needs torch >= 2.3 (ultralytics
# imports `torch.nn.attention`) and transformers 5 needs torch >= 2.5. Open3D 0.19 is the
# newest release and nothing is built against a newer torch, so the two cannot be met at
# once. This file freezes the old stack for the point-cloud work.
#
# Install into an environment of its own, never into .venv:
#
#     make install-o3dml
#     .venv-o3dml/bin/python segment_pcd.py ...
#     .venv-o3dml/bin/python cluster_pcd.py ...
#
# Both point-cloud scripts belong here now: segment_pcd.py because of the learned models
# (RandLA-Net, PointTransformer), and cluster_pcd.py because plain Open3D is no longer in
# the main environment either. The `mapping` package resolves its Open3D-backed helpers
# lazily, so everything else -- the pipeline stages, the depth providers, the evaluation
# -- runs in the main environment without it.
#
# Describe Anything (DAM) lives here too, for the same reason in the other direction: its
# LLaVA-based code imports `no_init_weights` from `transformers.modeling_utils`, which
# transformers 5 removed, and the main environment needs transformers 5 for its local
# VLMs. The annotation stage only reads the segmentation artefacts from disk, so it runs
# from this interpreter without touching the other stages:
#
#     .venv-o3dml/bin/python annotation.py --annotator dam ...
