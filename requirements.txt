# The floor is transformers 5, which needs torch >= 2.5: below that it disables PyTorch
# outright and no model can be loaded. transformers 5 is in turn what recognises the
# `qwen3_5_moe` and Gemma 4 architectures of the local image-capable models.

torchvision==0.20.1+cu121
torchaudio==2.5.1+cu121

# Pinned because it is the tightest constraint in the stack: every xformers release
# requires one exact torch version (0.0.28.post3 -> torch 2.5.1). It arrives
# transitively through Depth Anything 3, which asks only for an unpinned `xformers`, so
# without this line pip is free to leave a build compiled against a different torch.
xformers==0.0.28.post3

# The local models of LLM/conf/hf_*.yaml. Version 5 is what knows the image-text-to-text
# architectures of the Qwen 3.5/3.6 and Gemma 4 checkpoints; on 4.57 their configuration
# cannot even be parsed. Depth Anything V2 is unaffected: AutoImageProcessor and
# AutoModelForDepthEstimation behave the same across the major version.
transformers==5.16.1

# ------------------------------------------------------------------
# Open3D is deliberately absent.
#
# Open3D 0.19 ships precompiled PyTorch ops, and `open3d.ml.torch` refuses to load
# unless torch is 2.2.*, which the torch above is not. 0.19 is the newest release and
# nothing is built against a newer torch, so the two cannot be reconciled here.
# The point-cloud work therefore lives in its own environment: see
# requirements-o3dml.txt and `make install-o3dml`.
#
# `mapping` imports its Open3D-backed helpers lazily, so the pipeline stages, the depth
# estimators and the evaluation all work without it.
